# 接线说明（ESP32 + ASR PRO 无线烧录）

[English](wiring.md)

ESP32 和 ASR PRO 都是 3.3V 电平，信号线直接相连，不需要电平转换。一共三组线：

```
 ESP32                        ASR PRO
 ─────                        ───────
 GPIO9  ───────────────────→  PB6   下载口 RX   ┐ 1. 下载口（烧录用，必接）
 GPIO10 ←───────────────────  PB5   下载口 TX   ┘
 GPIO2  ───────────────────→  PA6   串口 RX     ┐ 2. 业务串口（通知 ASR 重启进入下载模式）
 GPIO1  ←───────────────────  PA5   串口 TX     ┘
 GND    ────────────────────  GND               3. 共地
```

| ESP32 | ASR PRO | 用途 |
|---|---|---|
| GPIO9（TX） | PB6（UART0 RX） | 下载数据：电脑 → ASR |
| GPIO10（RX） | PB5（UART0 TX） | 下载应答：ASR → 电脑 |
| GPIO2（TX） | PA6（Serial2 RX） | 发送 `<asr_isp>` 重启命令 |
| GPIO1（RX） | PA5（Serial2 TX） | 收到 `<asr_isp:ok>` 回复 |
| GND | GND | 共地 |

引脚可以换：示例代码里 TX/RX 都是常量，改成你实际接的引脚即可。ASR 一侧的下载口固定是 PB5/PB6（芯片手册 UART0），业务串口用哪对引脚取决于你的 ASR 程序。

## 烧录前

- **拔掉 ASR 板上的 USB 线。** 板载 USB 转串口芯片（CH340K）的发送脚也接在 PB6 上，插着 USB 时它会和 ESP32 的 GPIO9 同时驱动这根线，烧录会失败。如果一定要同时插 USB，在 GPIO9 与 PB6 之间串一个约 1 kΩ 电阻。
- ASR 里运行的程序要能处理 `<asr_isp>` 重启命令（见 `examples/asrpro/`）。第一次只能用 USB 线按普通方式把这样的程序烧进去，之后都可以无线烧录。
- 如果 ASR 程序不认识这个命令（或程序已损坏），可以在烧录软件等待时手动给 ASR 断电再上电，ESP32 同样能接住。

## 为什么是这三组线

ASR PRO 上电后约 850 毫秒内，如果下载口收到同步字节和握手包，就进入下载模式；否则正常运行用户程序。官方 USB 板靠 DTR/RTS 控制三极管给芯片断电再上电来制造这个时机。走 Wi-Fi 没有这两根控制线，所以：

1. ESP32 用**业务串口**发 `<asr_isp>`，ASR 程序回复后软件复位；
2. ESP32 立刻在**下载口**发同步字节和握手包，接住刚启动的 bootloader；
3. bootloader 被接住后会一直等待，电脑上的官方工具随后经 Wi-Fi 接手完成下载。

## 线接错时会看到什么

本程序“准备情况”里的提示和对应原因：

| 提示 | 常见原因 |
|---|---|
| ASR 没回应重启命令 | 业务串口两根线接反、没共地，或 ASR 程序里没有 `asr_isp` |
| ASR 收到了重启命令，但下载口没响应 | GPIO9/10 与 PB6/PB5 接反或没接，或 ASR 的 USB 没拔 |
| ESP32 连不上 | ESP32 没开机、和电脑不在同一个网络，或地址填错 |

ESP32 的 `GET /api/maintenance/status` 里也能看到：`lastAppAck` 表示 ASR 是否回复了重启命令，`caught` 表示下载口是否接住了 bootloader，`lastCatchRx` 是下载口收到的原始字节。

## 供电

两块板可以分别供电，但一定要共地。ASR 带喇叭工作时电流较大，不要用 ESP32 的 GPIO 给它供电。如果以后想让 ESP32 能给 ASR 硬断电（用于救回烧坏的程序），需要在 ASR 的 5V 线上加一个 MOS 管开关模块，由 ESP32 的一个 GPIO 控制。
