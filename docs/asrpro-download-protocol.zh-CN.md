# ASR PRO 官方下载协议（抓包整理）

[English](asrpro-download-protocol.md)

本文是用 com0com 端口对加转发脚本，旁听天问Block 0.2.8 自带的 `makebin.exe` 给 ASRPRO-4M 完整烧录一次后整理的结果。帧格式与 CRC 已用设备方向的 1700 多帧全部校验通过。标“推测”的字段没有官方文档佐证。本项目不依赖这些细节，只做透明转发，整理出来是为了方便排查和理解。

## 调用方式

```text
makebin.exe "&serial=COMx&chip=ASRPRO-4M&file=fw.bin&erase=false&lib=false&"
```

工作目录为天问Block 安装目录，固件是 `asrpro\fw.bin`。4MB 芯片要写 `ASRPRO-4M`。成功结尾为“复位设备成功 / 更新完毕”。

## 帧格式

```text
A5 0F | LEN(2B, 小端) | TYPE | CMD | FLAG | PAYLOAD(LEN 字节) | CRC16(2B, 小端) | FF
```

- `TYPE`：`A0` 主机命令，`A1` 设备请求或通知（主机握手也用 `A1`），`A2` 应答，`A3` 设备日志/进度文本。
- `FLAG`：主机命令里 `01` 多见于要求应答的查询或设置，应答里为 `00`（推测）。
- `CRC16`：CRC-16/XMODEM（多项式 0x1021，初值 0，不反转），范围从 `TYPE` 到 `PAYLOAD` 末尾，不含 `A5 0F` 和长度字段。
- 例：握手请求 `A5 0F 00 00 A1 83 00 67 C4 FF`，应答 `A5 0F 00 00 A2 83 00 37 9D FF`。

## 流程

### 0. 进入 bootloader

- 官方板子用 CH340K 的 DTR/RTS 控制三极管给芯片断电再上电，然后发 `0x55`×10 做速率同步，再发握手包。
- 芯片上电后约 850 毫秒内收到握手才进入 bootloader，否则运行用户程序。实测上电后 0–900 毫秒内握手都能成功。
- **bootloader 被握手抓住后会一直等**：先抓住，10 秒后再让 makebin 连接，照样烧录成功。makebin 自己也会反复重试握手。
- 用户程序调用 `dpmu_software_reset_system_config()` 软件复位后，同样会进入这个等待窗口。本项目的无线方案就是靠这一点。

### 1. ROM：115200 → 750000，下载 16 KB 加载器

| 方向 | 帧 | 含义 |
|---|---|---|
| 主→设 | `A1 83` | 握手 |
| 设→主 | `A2 83` | 握手应答 |
| 主→设 | `A0 85 01` | 查询；应答 payload `4E 00 00 00`（推测为版本） |
| 主→设 | `A0 0B 01` + `u32 波特率` | 切换波特率，`B0 71 0B 00` = 750000 |
| 主→设 | `A0 06 00` + `地址 u32, 长度 u32, u16` | 目标分区：`0x1FF58000`（内存），`0x4000` |
| 设→主 | `A1 08` + `偏移 u32, 0x1000 u32` | 设备按偏移逐包拉取 |
| 主→设 | `A2 08` + `偏移 u32` + 1024 字节 | 一包 1 KB |
| 设→主 | `A1 09` | 本分区接收完毕 |
| 主→设 | `A0 8A 00` | 校验并启动加载器；应答 payload `01` = 成功 |

每次切换波特率前，主机都会关闭再重新打开串口。

### 2. 加载器：115200 → 1500000，写 Flash

| 方向 | 帧 | 含义 |
|---|---|---|
| 设→主 | `A1 03` | 加载器就绪 |
| 主→设 | `A0 05 01` | 握手 |
| 主→设 | `A0 0B 01` + `60 E3 16 00` | 切到 1,500,000 |
| 主→设 | `A0 06 00` + `0, 0x19F000, 0000` | 目标分区：Flash 0 起 0x19F000 |
| 主→设 | `A0 07 00` + `0, 0x400000, 0x1000` | 擦除（地址、长度、扇区大小，推测） |
| 设→主 / 主→设 | `A1 08` / `A2 08` | 同上，逐 1 KB 拉取 |
| 设→主 | `A3 11` + 文本 | 进度，如 `0:65536/1699840` |
| 主→设 | `A0 0A 00` + `0, 0x19F000, crc16` | 分区校验；应答 payload `01` = 通过 |
| 主→设 | `A0 A1 00` | 复位设备 |

## 对无线转发的意义

- 数据由设备主动拉取，每包都有应答，所以对网络延迟不敏感。1,500,000 波特率下转发端需要足够的 UART 接收缓冲（ESP32 示例为 8 KB）。
- DTR/RTS 断电复位走不通无线链路，所以改为由 ESP32 通知 ASR 程序软件复位、在下载口先接住 bootloader，再交给 makebin。makebin 等待阶段发出的 `0x7F` 和 DTR/RTS 动作被忽略，不影响后面的握手。
